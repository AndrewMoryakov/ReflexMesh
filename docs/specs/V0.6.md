# V0.6 — Task API over MCP, Pi integration, and handoff

Status: proposed implementation specification, revision 1 (2026-10-03). Builds on [V0.5](V0.5.md); the [invariants](../architecture/INVARIANTS.md) govern this specification, in particular INV-01 (Pi is a client, not a dependency), INV-11 (no blind repeat) and INV-12 (handoff preserves task meaning).

## 1. Scope

Roadmap exit criterion: *Pi passes a task, receives a result or a blocker, and sends the next subtask.* V0.6 adds:

1. A transport-neutral **Task API** (`reflexmesh.api.TaskService`): submit, status/result, cancel, continue.
2. An **MCP stdio server** (`reflexmesh mcp`) exposing that API as tools; no third-party dependency.
3. A **handoff** object in every non-completed result, including a concrete `needs_content` case.
4. A **continuation** that creates a linked attempt with the remaining chain budget.
5. A separate **Pi package** in `integrations/pi` (extension + skill). The core never imports Pi.

Out of scope: HTTP Task API, durable queues, resuming a browser session, desktop, new executors, automatic recovery, and any expansion of permissions through handoff.

## 2. One semantics for every transport (INV-01)

Each attempt is executed by the existing `reflexmesh run` CLI in a child process, with the same supervisor, deadline, cancellation (SIGINT), evidence and result files. The service only prepares inputs, starts the process, observes its result, and records chain links. Therefore a task submitted through MCP and the same task given to the CLI produce the same `execution-result` schema, stop reasons and exit statuses. `run` gains `--attempt-id` so the service can name the attempt before it starts; its value is 32 lowercase hex characters.

## 3. Result schema change

`execution-result/0.2` = `execution-result/0.1` plus:

| Field | Contract |
|---|---|
| `handoff` | `null` for `completed`; otherwise a `handoff/0.1` object (section 4) |
| `chain` | `{root_attempt_id, parent_attempt_id, sequence}`; a standalone attempt is its own root with sequence 1 |

No other field changes meaning.

## 4. Handoff (INV-12)

A handoff returns control to the client. It is not completion of the goal and grants no permission. Fields:

| Field | Content |
|---|---|
| `kind` | `needs_content`, `blocked`, `incomplete`, `cancelled`, `failed`, or `unknown_effect` (precedence: `unknown_effect` > `needs_content` > status) |
| `task` | `task_id`, `revision`, `goal` |
| `attempt` | `attempt_id`, chain fields, `executor_id` |
| `stop` | `attempt_status`, `stop_reason`, `task_outcome` |
| `actions` | per committed action: `operation`, `target_id`, `slot_ref`, and `outcome` = `done` (effect applied), `not_done` (effect not applied), `possibly_done` (effect unknown) |
| `attempted` | whether any goal-directed action (beyond bootstrap navigation) was committed |
| `verification` | criterion and constraint IDs with status |
| `needs` | for `needs_content`: `{kind: "content", target_id, reason}` per gap (section 5) |
| `remaining_budget` | chain-level `steps`, `model_calls`, `wall_seconds` |
| `constraints` | `permissions`, `allowed_executors`, declared `text_slot_refs` (never values), `start_path`, fixture origin |
| `evidence_refs`, `trace_ref` | links to the attempt artifacts |
| `continuation` | `{allowed, reason}`; `allowed=false` with `unresolved_effect` when any non-navigation action is `possibly_done` |

The receiver can distinguish *not attempted*, *done* and *possibly done* without repeating the last action blindly.

## 5. Content gaps

ReflexMesh never authors text: micro decisions choose declared slot references only. When the final browser observation of an attempt contains an enabled text field with the HTML `required` attribute that is empty, the adapter reports that fixture target as a content gap. A non-completed attempt with at least one gap yields `kind=needs_content`. The client prepares the content and continues with a new revision that declares a new slot.

The fixture gains one page for this: `/support` with name, email and a required message field (`support-*` targets, `send-support` = `submit_form`). The predicate `support_request_sent_once` (`name_slot`, `email_slot`) passes when exactly one accepted `POST /support` since baseline carries the exact name/email slot values and a message equal to the value of some declared slot. Content that did not come from a declared slot cannot pass.

## 6. Continuation (INV-11, INV-12)

`continue(parent_attempt_id, changes)` is accepted only when the parent is terminal and its handoff allows continuation. `changes` may contain `goal`, `add_text_slots`, `criteria`, `start_path`, `fixture`, and `permissions`.

- Any change to goal, slots or criteria creates revision `parent.revision + 1`; otherwise the revision is unchanged. Existing slot ID/version pairs are immutable; a changed value needs a new version.
- `permissions` may only be a subset of the parent's permissions. Executors are inherited. Expansion requires a new task submitted outside the chain.
- Limits are the chain root's limits minus the total used by every attempt in the chain: steps, model calls, and elapsed wall time. A continuation is refused with `budget_exhausted` when any remainder is below one step, one model call, or one second.
- The new attempt has a new attempt ID, a fresh browser session, a fresh baseline and fresh observations. The parent executor has no authority left.

## 7. MCP server

`reflexmesh mcp --state-dir DIR --chrome FILE [--jev-url URL] [--max-concurrent 1]` speaks MCP over stdio: newline-delimited JSON-RPC 2.0, `initialize` (protocol versions 2024-11-05 through 2025-11-25), `notifications/initialized`, `ping`, `tools/list`, and `tools/call`. Logs go to stderr only.

| Tool | Arguments | Annotations |
|---|---|---|
| `reflexmesh_submit` | `task`, `routing_provider`, `action_provider`, optional `script` | not read-only; closed world |
| `reflexmesh_status` | `attempt_id`, optional `wait_seconds` (0–50), `detail` = `summary`/`full` | read-only, idempotent |
| `reflexmesh_cancel` | `attempt_id` | idempotent |
| `reflexmesh_continue` | `parent_attempt_id`, `changes`, providers, optional `script` | not read-only; closed world |

Input errors return `isError=true` with a code (`invalid_input`, `unknown_attempt`, `busy`, `not_terminal`, `continuation_refused`, `budget_exhausted`, `unresolved_effect`) and never start an attempt. Tool results carry the JSON both as text and as `structuredContent`. Status waits are bounded so a call returns well within the client's default 60 s timeout. On stdin EOF or SIGTERM the server cancels running attempts through SIGINT and reaps them within G + K + 1 seconds before exiting.

## 8. Pi integration

`integrations/pi` is a Pi package (`reflex-mesh-pi`): an extension that registers the MCP server for a session from environment configuration, and a skill describing the client protocol (submit → wait → on handoff decide → continue; slots carry exact text; a handoff is never success). Pi stays optional: the same tools work from any MCP client, and from the CLI.

## 9. Acceptance

| ID | Level | Subcases and expected outcome |
|---|---|---|
| A01 | U | MCP handshake, tool listing, schema errors, unknown attempt, busy: exact codes; no attempt started on error |
| A02 | U | CLI and MCP yield the same result fields and stop reason for the same blocked task |
| A03 | U | Handoff fields for blocked, cancelled and unknown-effect results; `possibly_done` refuses continuation |
| A04 | U | Continuation: revision rules, slot immutability, permission subset, chain budget arithmetic, exhaustion refusal |
| A05 | U | Server shutdown cancels and reaps a running attempt within the bound |
| A06 | B | Through MCP: form task → completed/pass, three fresh fixtures |
| A07 | B | Through MCP: support task without message → `needs_content` handoff naming `support-message`; continuation with a new slot → completed/pass; one accepted POST; chain budget decreases; three times |
| A08 | B | Through MCP: cancel during a held decision → cancelled; no later dispatch; three times |
| A09 | Pi | A real Pi session using the package completes A07 by authoring the message itself, once, with the transcript and results preserved |
| A10 | B | V0.5 B regression subset (C01, C03, C05) still passes on the V0.6 commit |

Missing environments leave rows pending. Failures are recorded, not replaced.
