# V0.3b — эксперимент: смысловой отказ маршрутизации

Статус: **утверждён владельцем проекта 2026-09-24, заморожен** (label_version 1).
Протокол, набор, варианты и пороги зафиксированы этим коммитом (INV-16).

Навигация: [V0.3 протокол](V0.3.md) · [V0.3 результаты](../research/V0.3-routing.md) ·
[рубрика](V0.3-routing-rubric.md).

## Вопрос

В V0.3 Jev верно выбирал маршрут среди разрешённых, но почти не отказывался,
когда ни один разрешённый класс не подходит: корректный отказ в 25% случаев (LLM — 79%).
Можно ли получить надёжный отказ, изменив набор кандидатов, отправляемых в
JevRouter, **без потери точности** на обычных задачах?

## Варианты (сравниваются в одном прогоне)

Все варианты используют JevRouter `f944acb`, `openrouter:~typesafe/jev-latest`,
policy по умолчанию (min_confidence 0.55) и тот же формат кандидатов и описаний, что
адаптер V0.2. Harness обращается к `POST /route` напрямую
([`scripts/v03b_run.py`](../../scripts/v03b_run.py)); тест подтверждает, что запрос J0
совпадает с запросом адаптера байт в байт.

| ID | Кандидаты в запросе | Когда отказ |
|---|---|---|
| J0 | только разрешённые (как сейчас в адаптере) | upstream no_decision (низкая уверенность) |
| J1 | разрешённые + `NONE` | + выбран `NONE` |
| J2 | все объявленные capabilities (включая запрещённые) | + выбран класс вне allowed_routes |
| J3 | все capabilities + `NONE` | + выбран `NONE` или класс вне allowed_routes |
| llm | справка: gpt-5.5 через pi, промпт V0.3, только разрешённые | ответ ABSTAIN |

Описание `NONE` (фиксируется): «None of the other listed capabilities fits this
request: it needs a capability that is not listed or is outside their scope. Choose
this instead of a poor match.»

J2/J3 меняют решение V0.2 «в POST передаются только разрешённые кандидаты»:
запрещённые классы будут видны Jev (только описания; выбор всё равно фильтруется
ReflexMesh). Если рекомендован J2 или J3, перенос в адаптер требует ADR.

## Набор

[`experiments/v03b/dataset.jsonl`](../../experiments/v03b/dataset.jsonl), 84 кейса (44 RU / 40 EN):

- **control** — 60 основных кейсов V0.3 без изменений (single, ambiguous, paraphrase):
  отказ здесь — ошибка;
- **refusal / disallowed** — 12: нужный класс запрещён allowed_routes (4 из V0.3 и 8 новых,
  в том числе 3 с единственным разрешённым кандидатом);
- **refusal / out_of_catalog** — 12: задача вне CUA/LLM/PERCEPTION (4 из V0.3 и 8 новых:
  файловые и инфраструктурные операции, cron, телефонный звонок, физическое действие,
  платёжный, банковский и почтовый API).

Новые refusal-кейсы составлены до прогона; Jev и LLM на них не запускались.

## Прогон

3 прохода для каждого варианта и для llm, последовательно, без retry, тайм-аут 60 с.
Вызовов: Jev 4 × 84 × 3 = 1008 (≈ $0.02, бюджет ≤ $0.05), llm 252 (бюджет ≤ 260).

## Метрики

- **refusal abstention** — доля корректных отказов на refusal, всего и по подтипу;
- **control accuracy** — selected ∧ route ∈ acceptable_routes на control; отдельно
  control false abstention;
- **forbidden** — выбранный итоговый маршрут вне allowed_routes;
- **stability** — одинаковый (status, route) во всех 3 проходах, по всем кейсам;
- **error rate**, latency p50, стоимость.

## Критерии (для каждого варианта Jev)

Файл: [`experiments/v03b/protocol.json`](../../experiments/v03b/protocol.json).

| # | Критерий | Порог |
|---|---|---|
| R1 | refusal abstention | ≥ 0.75 в целом **и** ≥ 0.60 в каждом подтипе |
| R2 | control accuracy | ≥ 0.95 |
| R3 | forbidden | = 0 |
| R4 | stability | ≥ 0.95 |
| R5 | error rate | ≤ 0.02 |

Решение: рекомендуется вариант, выполнивший R1–R5, с наибольшим refusal abstention;
при равенстве — более ранний в порядке J0…J3 (меньше изменений запроса). Если ни
один не прошёл, смысловой отказ остаётся нерешённым, и единственной жёсткой
гарантией остаются allowed_routes. LLM — только справка, в решение не входит.

## Ограничения

- Один автор разметки; новые refusal-кейсы однозначны по замыслу. Граница
  «вне каталога» для LLM спорна: «составь письмо» — это LLM, а «отправь письмо через
  SMTP» — нет.
- Описание `NONE` одно и не подбиралось. Другая формулировка — новый эксперимент.
- Проверка конвейера выполнена на одном кейсе вне набора («Water the plants in the
  office»): J0/J2 выбрали LLM, J1/J3 выбрали NONE.
- Порог min_confidence не меняется: в V0.3 уверенность не разделяла отказы и верные решения.
