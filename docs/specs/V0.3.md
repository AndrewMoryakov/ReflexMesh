# V0.3 — протокол эксперимента маршрутизации

Статус: **утверждён владельцем проекта 2026-09-24, заморожен** (label_version 1).
Протокол, набор, правила baseline и пороги зафиксированы этим коммитом;
commit фиксируется в отчёте. Изменение любого из них
после получения результатов — новый, явно обозначенный эксперимент (INV-16).

Навигация: [рубрика](V0.3-routing-rubric.md) · [ROADMAP](../ROADMAP.md) ·
[INV-16](../architecture/INVARIANTS.md) · [V0.2](V0.2.md).

## Вопрос

Полезен ли Jev (через JevRouter и адаптер V0.2) для выбора класса исполнителя
CUA / LLM / PERCEPTION по сравнению с простыми правилами и универсальной LLM
при сопоставимых задержке и стоимости? Исполнение задач не оценивается:
правильный маршрут ≠ выполненная задача.

## Набор задач

Файл: [`experiments/v03/dataset.jsonl`](../../experiments/v03/dataset.jsonl), 75 кейсов
(40 RU, 35 EN). Разметка по [рубрике](V0.3-routing-rubric.md).

| kind | Кол-во | Смысл | Ожидаемый исход |
|---|---|---|---|
| single | 30 (по 10 на класс) | Однозначная атомарная подзадача | selected, route ∈ acceptable_routes |
| ambiguous | 15 | Поверхностные признаки вводят в заблуждение (упомянут браузер/скриншот, но нужна другая работа); допустимое множество задано заранее | selected, route ∈ acceptable_routes |
| paraphrase | 15 (по 5 на класс) | Естественные формулировки пользователя без явных триггеров («сохрани изменения в профиле», «что написано на картинке?»): проверка обобщения за пределы заранее известных слов | selected, route ∈ acceptable_routes |
| refusal | 8 | Нужный класс запрещён allowed_routes (4) или задача вне каталога (4) | abstained / no_decision, без выбора |
| composite | 7 | Неразделённая многошаговая цель | описательно, вне accuracy |

Поля: `case_id, lang, kind, goal, capabilities, allowed_routes, acceptable_routes,
expected_outcome, rationale`. `goal` самодостаточен: описание доступных входных данных
(«дан скриншот…», «текст ошибки приведён ниже…») включено в текст, потому что
Task 0.1 передаёт маршрутизаторам только goal. Автор разметки: агент pi (Claude);
ревьюер: владелец проекта. Эталон не передаётся маршрутизаторам.

## Сравниваемые маршрутизаторы

Все получают одинаковые goal и одинаковый набор кандидатов
(пересечение capabilities и allowed_routes) с описаниями `DESCRIPTIONS` из
`src/reflexmesh/routing/jev_router.py`.

| ID | Что | Как вызывается |
|---|---|---|
| `rules` | Детерминированные ключевые слова RU/EN: [`experiments/v03/rules.py`](../../experiments/v03/rules.py) | Локально; нет совпадений или ничья → abstain |
| `jev` | ReflexMesh CLI `--provider jevrouter` → JevRouter f944acb `serve --provider openrouter` → `typesafe/jev-latest` | Policy по умолчанию (min_confidence 0.55); абстенция — upstream no_decision |
| `llm` | Модель, подключённая в pi: `openai-codex/gpt-5.5`, уровень рассуждения по умолчанию pi | `pi -p --no-tools --no-extensions --no-skills --no-context-files --no-session`, фиксированный промпт из `experiments/v03/llm_prompt.md`; ответ `{"route": "<ID>"}` или `{"route": "ABSTAIN"}` |

Ответ LLM вне набора кандидатов считается нарушением ограничения (forbidden) и
неверным ответом; невалидный ответ — ошибкой. Повторов и исправлений ответа нет.

## Прогон и бюджеты

- Повторы: `jev` и `llm` — 3 прохода по всему набору (порядок кейсов одинаков);
  `rules` — 1 (детерминирован).
- Последовательные вызовы, без retry; тайм-аут 60 с на решение; ошибка/тайм-аут
  засчитывается как неверный ответ и учитывается в error rate.
- Бюджет: `jev` ≤ $0.05 (ожидаемо ≈ $0.005 на 225 вызовов); `llm` ≤ 250 вызовов
  (подписка; стоимость — оценка pi по прайсу, иначе «неизвестно»).
- Среда: Linux-хост оператора, прямой доступ к OpenRouter (без туннеля),
  JevRouter `f944acb` на loopback. Receipts JevRouter сохраняются.
- Латентность — wall-clock от запуска процесса маршрутизатора (CLI ReflexMesh
  или pi) до его завершения; одинаково включает старт процесса у `jev` и `llm`.
  Отдельно фиксируется накладной старт pi на пустом запросе.

## Метрики

Считаются по всем проходам (case-runs); рядом приводится вариант «по большинству
из 3 проходов».

- **accuracy** (single+ambiguous+paraphrase; также раздельно по kind и языку):
  status=selected ∧ route ∈ acceptable_routes.
- **coverage**: доля selected; **abstention**: доля отказов; **error rate**: ошибки
  транспорта/провайдера/формата.
- **forbidden**: число выборов маршрута вне allowed_routes (по всему набору).
- **refusal abstention**: доля корректных отказов на refusal.
- **stability**: доля кейсов, где все 3 прохода дали одинаковый (status, route).
- **latency** p50/p95; **calls** на решение; **стоимость** суммарно и на решение.
- **composite**: распределение исходов, без оценки корректности.

## Критерии принятия (предлагаемые, утверждаются до прогона)

Файл: [`experiments/v03/protocol.json`](../../experiments/v03/protocol.json).

| # | Критерий | Порог |
|---|---|---|
| T1 | accuracy `jev` (single+ambiguous+paraphrase) | ≥ 0.85 |
| T2 | accuracy `jev` − accuracy `rules` на **paraphrase** (обобщение на непредусмотренные формулировки) | ≥ +0.10 |
| T3 | accuracy `jev` − accuracy `llm` | ≥ −0.05 |
| T4 | forbidden `jev` | = 0 |
| T5 | stability `jev` | ≥ 0.95 |
| T6 | error rate `jev` | ≤ 0.02 |

Решение:

- **Jev полезен** — выполнены T1–T6: Jev рекомендуется для macro-routing в
  этом каталоге вместо LLM-маршрутизатора.
- **Jev приемлем, преимущество не подтверждено** — выполнены T1, T2, T4, T5, T6,
  но не T3.
- **Полезность не подтверждена** — не выполнен любой из T1, T2, T4, T5, T6.

Гипотеза: Jev сопоставим с LLM по качеству при многократно меньшей стоимости (T3)
и обобщает лучше правил, которые не могут предусмотреть все будущие формулировки (T2).
Общая accuracy `rules` публикуется для справки.

Латентность и стоимость публикуются для всех маршрутизаторов, но в решение не входят:
LLM заведомо дороже и медленнее Jev и правил, поэтому к ней сравнение идёт по
качеству (T3). Accuracy на paraphrase публикуется отдельно для всех сравниваемых.

Refusal и composite публикуются отдельно и в решение не входят: в адаптере нет
механизма смыслового отказа ([рубрика](V0.3-routing-rubric.md)). Выводы относятся
только к этому набору, каталогу и конфигурации; 75 кейсов — пилотный масштаб,
доверительные интервалы (Wilson 95%) приводятся рядом с accuracy.

## Известные ограничения и что сделано до утверждения

- Набор и правила `rules` составлены одним автором; ключевые слова rules писались
  одновременно с набором, что может завышать их точность.
- При составлении автор один раз запустил `rules` на наборе как smoke-проверку
  (37/45 на single+ambiguous). После этого правила **не менялись**; это значение не
  является результатом эксперимента и будет пересчитано в прогоне.
- Кейсы paraphrase добавлены после обсуждения с владельцем: правила не могут
  предусмотреть все формулировки. Автор знает ключевые слова rules, поэтому набор
  paraphrase намеренно проверяет обобщение и не является случайной выборкой запросов;
  результат rules на нём заранее не вычислялся.
- `jev` и `llm` на кейсах набора не запускались. Проверка конвейера выполнена
  на одном кейсе вне набора (Jev ≈ 0.6 с, pi/gpt-5.5 ≈ 6.5 с на решение).
- Латентность `llm` включает старт pi (несколько секунд), латентность `jev` — старт
  Python CLI; это свойство сравниваемых интеграций, а не только моделей.
- Стоимость `llm` — оценка pi по прайсу модели; фактически вызовы идут по подписке.
