## Вне решения (публикуется отдельно по протоколу)

**Refusal, 8 кейсов × 3 прохода: здесь Jev слаб.** Корректный отказ: jev 6/24 (0.25),
llm 19/24 (0.79), rules 7/8.

- Нужный маршрут запрещён (R-01…R-04): Jev **всегда выбирает ближайший разрешённый
  маршрут** (например, «нажми «Оплатить»» при allowed=LLM,PERCEPTION → LLM).
  LLM в 3 из 4 случаев отказывается.
- Вне каталога (R-05…R-08): Jev отказался на `git pull` и REST (confidence 0.26–0.45 ниже
  порога 0.55), но выбрал LLM для SMS через API и запроса к PostgreSQL (0.68–0.94).
- Причина: Jev решает вопрос «какой из кандидатов лучше подходит», а не
  «подходит ли какой-нибудь кандидат». Порог уверенности это не исправляет: для
  отказов confidence 0.26–0.94, для верных решений на основном наборе — от 0.82.
  Разделить их одним порогом нельзя (**наблюдение, порог не подбирался**).
- Запрещённый маршрут ни Jev, ни LLM ни разу не выбрали: фильтр ReflexMesh до
  отправки работает (T4).

**Composite, 7 кейсов:** все маршрутизаторы обычно выбирают первый шаг
(CUA/PERCEPTION); Jev отказался на 2 кейсах (C-04, C-06, confidence 0.27–0.45).
Декомпозиция не оценивалась.

## Интерпретация и ограничения

- **Эффект потолка.** Jev и LLM набрали 100% на основном наборе: набор
  не разделяет их по качеству. T3 выполнен, но разница в точности, которую можно
  было бы заметить, ограничена сложностью кейсов. Для оценки на трудных случаях
  нужен набор сложнее, без явных подсказок о входных данных.
- **Правила.** Ключевые слова писал тот же автор, что составлял набор, поэтому
  0.933 на single — оптимистичная оценка. На paraphrase правила чаще всего не
  срабатывали (abstain), а не ошибались: это отказ, а не ложный выбор.
- **Масштаб.** Один автор разметки, 45 основных кейсов, одна конфигурация и один прогон.
  Вывод относится к этому каталогу из трёх классов, а не к маршрутизации вообще.
- **LLM-стоимость** — оценка pi, латентность включает старт процесса pi
  (~несколько секунд). Даже без старта LLM-решение с рассуждением медленнее Jev.
- **Практический вывод для архитектуры.** Jev подходит для macro-routing между
  разрешёнными классами. Смысловой отказ («ни один класс не подходит») Jev
  не обеспечивает, поэтому его нужно решать отдельно: явными запретами ReflexMesh
  (как уже сделано через allowed_routes), отдельным вопросом к Jev «подходит ли
  хоть один?» или правилом каталога. Любое изменение — новый эксперимент по INV-16.
