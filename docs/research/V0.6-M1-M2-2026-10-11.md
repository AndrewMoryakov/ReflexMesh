# V0.6 M1–M2: первый прогон общего браузерного пути, 2026-10-11

Датированный отчёт о том, что реализовано и запускалось для M1–M2 [V0.6](../specs/V0.6-browser-core.md),
и о том, что нет. Он не закрывает ни один gate V0.5, не меняет исторических результатов и не
означает готовности browser MVP: приёмка M1–M2 подтверждает только свой участок.

Кодовая база: ветка `integrate/v0.6-into-main` (локальная, не отправлена), `main` на `a8e87bf` влит.
Прогоны ниже сделаны на `e5187be`, за исключением CLI-прогона в папке свидетельства — он сделан на
`fc765d6` (последующие коммиты поменяли расчёт покрытия и обработку повторов, сценарий свидетельства их не затрагивает).

## Что реализовано

- **Контракт** `browser-task/0.1` (`contracts/browser.py`): строгий вход ≤ 64 KiB без дублей ключей и NaN, без `fixture`, канонические origins, конечные лимиты, слоты с `sensitivity`. Критерий неизвестного predicate и любое запрошенное ограничение дают `blocked/unsupported_criterion` / `unsupported_constraint`, а не молчаливый запуск.
- **Шлюз** `AttemptGate` берёт таблицу операций из задачи (у fixture-задач она прежняя): браузерные операции проверяются при commit, а не считаются `unchecked`.
- **Адаптер** `GenericBrowserAdapter`: варианты строятся из дерева доступности страницы без сценария сайта; каждый вариант привязан к узлу, frame и документу; перед диспатчем идёт свежий захват и сравнение (`stale_target` иначе). Предлагаются `click`, `type_text`, `select_option`, `scroll`, `wait`, `go_back`, `switch_tab` и первая навигация.
- **Провайдеры**: script по описаниям вариантов; валидатор, превращающий любой ответ с не предложенной операцией/целью/значением или нечисловой оценкой в `failed/protocol_error`; Jev из окружения с `retries=0`.
- **Прогон** (`runtime/browser_run.py`) и `reflexmesh browser run`: шаг на каждое наблюдение, вызов на каждый запрос к модели, каждая команда браузера через общий gate, редактируемый журнал JSONL.

## Что показал прогон M1 (script, реальный Chromium)

Задача: найти заказ №125, ввести заметку «Перезвонить завтра», сохранить. Сайт — обычные HTML-страницы без
какой-либо разметки ReflexMesh; в ядре нет сценария для него.

| Измерение | Результат |
|---|---|
| Исход | `incomplete / verification_unknown`, `task_outcome=unknown` (verifier M4 нет — `completed` невозможен), код выхода 4 |
| Бюджет | 7 шагов, 6 диспатчей (навигация, ввод, клик, клик, ввод, клик), 0 вызовов модели |
| Сервер-оракул | `notes == {"125": ["Перезвонить завтра"]}`, ровно один POST. Оракул читал только тест; цикл управления — нет |
| Строки ограничений | `permissions`, `dispatch_ordering`, `immutable_slots`, `budget` — **pass** по свидетельствам шлюза и реестра слотов; `ownership`, `no_uncertain_repeats` — **unknown** |
| Эффект | `ui_effect` показывает, что поле содержит значение слота (`field_shows_slot_value`), URL/содержимое сменились; серверный `effect` остаётся `unknown` |
| Очистка | браузер и профиль удалены (`cleanup.status=closed`, процессов не осталось) |

Цепочка в трассе для каждого действия: `observed` → `options_built` → `decision_requested` →
`decision_received` → `threshold_judged` → `proposal` → `dispatch_committed` → `driver_returned` →
`effect_assessed`. Текст заметки в трассе и результате отсутствует.

## Находки: что оказалось не так, как предполагал код

1. **Передача текста не работала на настоящем Browser Use.** `dispatch_text` читал `model.input`, но `create_action_model()` в закреплённом коммите возвращает объединение `RootModel` (`model.root.input`); любой реальный ввод текста отклонялся как `adapter_contract_unsupported`. Два «опциональных» теста V0.5 на настоящей модели раньше пропускались и никогда не проходили на ней. Исправлено (читаются обе формы); тесты приведены к реальной форме.
2. **Browser Use копирует нестандартный профиль Chrome** в `/tmp/browser-use-user-data-dir-*` и не удаляет копию (на этом хосте `/tmp` — ОЗУ). Профиль адаптера именуется с маркером этого префикса, после старта проверяется, что Chrome использует именно его, и удаляется.
3. **SOH читает `pixels_below` не там.** Смещение прокрутки лежит в `state.page_info`; поле верхнего уровня всегда 0, поэтому страница на 260 кнопок была бы названа полной. Покрытие читает `page_info`: такая страница — `partial` с `more_content_below`, `next_window=scroll`, а прокрутка открывает новые элементы.
4. **Скрытые повторы провайдера.** `DecisionProvider` SOH по умолчанию делает до 4 повторов с задержкой — запросы, которых бюджет не видит. Путь Jev создаёт провайдера с `retries=0`; тест: ответ 503 приводит ровно к одному запросу.
5. **Короткий `about:blank`** сразу после открытия новой вкладки принимался за чужой origin. Пустая страница — не нарушение политики; `switch_tab` допускается по целевой вкладке, а не по странице на переднем плане.
6. **Повтор безопасного действия считался нарушением.** Второй `wait`/`scroll` на неизменной странице давал строке `no_uncertain_repeats` статус fail и итог `failed/constraint_violated` (то же — любая команда после неудачного чтения). Строки с `risk=read` (scroll, wait, switch_tab) теперь исключены из этой оценки, а сбой чтения не делает эффект неизвестным; сбой записи по-прежнему блокирует следующие записи. Найдено при ревью до первого прогона с Jev.
7. **`observation_id` в полях наблюдения скрывал повторы.** SOH хэширует эти поля, чтобы заметить то же действие на том же состоянии; свежий id на каждом шаге делал каждое состояние «новым», и остановка `repeated_action` не могла сработать. Теперь id остаётся только в собственном отчёте; повтор на неизменной странице завершается `needs_handoff / no_progress` (тест). Правило §8 «три цикла без нового состояния, эффекта или движения к критерию» этим не реализовано — только случай «то же действие, то же состояние».
8. **Редирект на чужой origin обнаруживается, но не предотвращается.** Ссылка того же origin, которую сервер перенаправляет на другой, приводит к одному запросу к чужому origin; прогон останавливается `blocked/policy_denied` на следующем наблюдении, больше ничего не отправляется. Защита `allowed_domains` Browser Use сама срабатывает после навигации. Предотвращение требует перехвата `Fetch` на каждой вкладке — не реализовано; граница закреплена тестом.

## Что не сделано и неизвестно

- Настоящий Jev на этом пути (нет ключа); качество выбора, цена и задержка не измерялись.
- Verifier и критерии (M4): `completed` недостижим; `ownership` и `no_uncertain_repeats` остаются `unknown`.
- Handoff с продолжением и сессией (M3): есть только пакет, объясняющий остановку, без токена.
- Операции: `press_key`, `focus_region`; возможности `frames`, `cross_origin_frames`, `open_shadow_dom` объявлены `false` и не проверялись пробами (F11).
- Правило §8 о трёх циклах без нового состояния не реализовано сверх проверки SOH «то же действие на том же состоянии».
- Цикл работает в вызывающем процессе (с потоком-сторожем), а не в изолированном процессе под supervisor; F05 для него не прогонялся полностью.
- Предел в 200 элементов (`control_limit`) тестом не воспроизведён; воспроизведена только неполнота из-за окна просмотра.
- Нет Windows-варианта: путь использует `fork` и `/proc`.
