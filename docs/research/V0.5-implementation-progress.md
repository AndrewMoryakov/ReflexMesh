## Open acceptance work

The [V0.5 acceptance matrix](../specs/V0.5.md#9-fixed-acceptance-gate-r7) has not been frozen into a complete subcase manifest. The deterministic tests are useful implementation checks, but do not yet establish every U subcase in that matrix. **All B and J subcases are pending**, including three fresh-fixture repetitions per subcase. There is no Jev micro-provider or JevRouter macro live receipt in this implementation pass.

Known implementation gaps against the specification:

1. CLI fixture preflight and macro routing happen before the supervisor starts its deadline. Macro calls are not charged to `max_model_calls`; a stalled preflight/routing call is not bounded by the complete attempt lifecycle.
2. The real Browser Use selector-map and backend-node behavior has only simulated tests; page/frame identity, destination/form identity, and live policy-revocation checks still need browser evidence and, where necessary, implementation changes.
3. Result/evidence fields and runtime constraints do not yet meet the full section 6/8 schema: action sequences, per-criterion observation times, persisted redacted evidence, sticky constraint assessments, late reconciliation, and measured model cost are incomplete.
4. The gate has a bounded lock wait, but a worker crash while holding the lock and full process-tree cleanup timing have not been demonstrated with the required acceptance fixtures.

Next: close these contract gaps, install a working Chromium binary, freeze the subcase manifest, run U and B at their required repetition counts, then run J with configured live providers. Update milestone status only after recording each planned attempt and its evidence.
