## Open acceptance work

All listed U subcases from the [V0.5 acceptance matrix](../specs/V0.5.md#9-fixed-acceptance-gate-r7) are represented in the frozen U manifest and passed once. **All B and J subcases are pending**, including three fresh-fixture repetitions per subcase. The U pass uses fakes and a local harness script; there is no Jev micro-provider or JevRouter macro live receipt in this implementation pass.

Known implementation gaps against the specification:

1. The real Browser Use selector-map and backend-node behavior has only simulated tests; page/frame identity, destination/form identity, and live policy-revocation checks still need browser evidence and, where necessary, implementation changes.
2. Action sequences, postcondition observation times, redacted evidence references, late effect reconciliation, and a budget constraint check are present. Other required runtime constraints and authoritative reconciliation of every unknown action are incomplete. Model cost remains unmeasured and explicitly null.
3. The gate has a bounded lock wait, but a worker crash while holding the lock and full process-tree cleanup timing have not been demonstrated with the required acceptance fixtures.
4. The U manifest records each deterministic subcase, but the B/J manifest expansion, real dependency versions, exact live commands, provider identities, and repeated results remain to be frozen and collected.

Next: close the remaining adapter and runtime-contract gaps, install a working Chromium binary, freeze B/J subcase commands, run B three times per variant, then J three times per variant with configured live providers.
