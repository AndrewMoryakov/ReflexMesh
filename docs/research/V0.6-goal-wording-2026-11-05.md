# V0.6: как формулировка цели влияет на Jev, 2026-11-05

В [цепочке на Windows](V0.6-windows-2026-11-05.md) Jev на ревизии 2 не открывал найденный заказ, хотя в одиночном прогоне
открывал его уверенно. Страница и варианты действий в момент решения совпадают (одна подпись страницы), поэтому оставалось два
отличия: текст цели и неудачная первая попытка в том же браузере. Здесь они разделены.

Модель `typesafe/jev-1.14-20261014`, порог 0.70, демо-сайт заказов, Windows 11, Chrome 142. Цели:

```
короткая  Find order 125 in the order desk, add the prepared note to it and save the note.
длинная   The order number is now provided as order@1. Replace the text in the Order number field with order@1,
          search, open order 125, add the prepared note to it and save the note.
с фактом  Find order 125 in the order desk, add the prepared note to it and save the note.
          The order number is order@1; the search field may hold a wrong value.
```

Первая попытка: задача без значения `order@1` с короткой целью. Jev вводит в поле «Заказ №125», поиск ничего не находит, и он
передаёт управление. Вторая попытка идёт в том же браузере.

## Результаты

Сначала проверялись короткая и длинная цели, цель с фактом написана после этого и зафиксирована до её прогонов.

```
цель      браузер            прогонов  чем закончилось
короткая  свежий             9         9 completed/verified; ссылка на заказ 0.89-0.94
короткая  после 1-й попытки  5         0 дошли; неверное значение в поле не заменено, 0.28-0.42
длинная   свежий             5         0 дошли; номер и Search приняты, стоп на результатах, ссылка не выше 0.48
длинная   после 1-й попытки  7         0 дошли; номер и Search приняты, стоп на результатах, ссылка не выше 0.49
с фактом  свежий             5         0 дошли; номер принят, стоп на Search, 0.47-0.65
с фактом  после 1-й попытки  5         0 дошли; номер принят 0.77-0.85, стоп на Search, 0.29-0.46
```

Девять прогонов первой строки: 6 запускал владелец за своим рабочим столом, 3 запущены по SSH как контроль, чтобы разница не
объяснялась способом запуска. Семь прогонов строки «длинная, после 1-й попытки»: 4 владельца, 3 по SSH. Остальные по SSH.
Разброса между запусками внутри строки почти нет: в каждой строке все прогоны останавливаются на одном и том же шаге.

## Что из этого следует

- **Неудачная попытка не нужна, чтобы Jev застрял.** Длинная цель останавливает его на результатах и в свежем браузере.
- **Ни одна из трёх целей не проводит Jev через цепочку.** Короткая не исправляет поле после первой попытки. Длинная и с фактом
  его исправляют, но дальше останавливаются. Сам Jev в цепочке до конца не дошёл ни разу (0 из 17).
- **Предположение «мешает пошаговое описание» опровергнуто.** Цель с фактом шагов не перечисляет, а Jev останавливается раньше,
  чем с длинной. Эта цель предлагалась как решение и оказалась хуже.
- **Цель `chain_demo.REVISION_2_GOAL` не менялась:** из проверенных с ней Jev проходит дальше всего после первой попытки.

## Не установлено

- Почему добавленный к цели текст снижает уверенность. Обе более длинные цели упоминают `order@1`, но отдельно это не проверялось.
- Относится ли это к другим сайтам, задачам и версиям модели: всё снято на одном сайте и одной версии, по 5-9 прогонов на строку.
- Есть ли цель, с которой Jev пройдёт цепочку сам.

Свидетельства: [evidence/V0.6-goal-wording-2026-11-05](evidence/V0.6-goal-wording-2026-11-05/), решения по каждому прогону в
`summary.txt`. Каталоги `A` короткая и свежий, `B` длинная и свежий, `C` короткая и после попытки, `D` и `E` с фактом, `long-history`
длинная и после попытки, `owner-*` запускал владелец. По одному прогону первой строки и двум четвёртой лежат в
[свидетельствах отчёта о Windows](evidence/V0.6-windows-2026-11-05/) (`owner-jev`, `owner-chain-before-helper`, `chain-with-helper`).
