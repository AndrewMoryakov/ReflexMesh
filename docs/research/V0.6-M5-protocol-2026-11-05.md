# V0.6 M5: протокол сравнения и состояние приёмки, 2026-11-05

**Это не сравнение из раздела 17.** Здесь собран и проверен протокол, а прогон сделан на демо-сайте. Этот сайт весь день использовался для настройки runtime, а раздел 17 запрещает
настраиваться на сайтах набора, поэтому цифры ниже ничего не говорят о том, какой режим лучше, и не закрывают M5.

## Что сделано

- **Режим L:** провайдер `chat` (`--action-provider chat --model ...`). Обычная LLM выбирает каждое действие из тех же конечных вариантов, через тот же адаптер, gate, verifier и бюджет. Модель называется явно, значения по умолчанию нет. Запросы считаются в `max_model_calls`, повторов нет.
- **Порог для L:** LLM не сообщает калиброванной уверенности, поэтому порог 0.70 к её выбору не применяется, а остальные проверки gate применяются. Это решение записано в manifest и должно быть заморожено до сравнения.
- **Режим J1:** настоящая LLM в роли вызывающего агента, через `browser-progress`, с учётом вызовов, токенов и стоимости.
- **Исполнитель** `experiments/v06/m5/runner.py`: J0, J1 и L по manifest, чередование порядка режимов, строка на каждый запланированный запуск сразу по его окончании, успех по независимому oracle (читает записи сайта после прогона, управлению ничего не передаёт), отдельный счёт `false_completion`.
- **Стоимость** каждого запроса: `usage.cost` для LLM и `/api/v1/generation` для Jev. Если для запуска она неизвестна, итог режима тоже неизвестен, а не занижен.

## Проверка протокола

Задачи `order-note` и `wizard-note`, по 3 повтора в 3 режимах, 18 запусков на Windows 11, Chrome 142. Jev `typesafe/jev-1.14-20261014`, LLM `anthropic/claude-haiku-5.5`.

```
режим  подтверждено  ложных completed  wall p50 / p95, с  вызовов на запуск  стоимость 6 запусков, $
J0     6 из 6        0                 24.0 / 25.7        5                  0.0016
J1     6 из 6        0                 26.1 / 27.8        5                  0.0016
L      6 из 6        0                 31.7 / 37.1        5                  0.0066
```

Медианная задержка решения: Jev 0.64 с, LLM 2.48 с. Wall включает запуск браузера и сайта и не сравнивает одни решения. В первой версии L дал 2 из 6, но это была ошибка разбора ответа, а не модели: `response_format` на этом маршруте не соблюдается, и модель иногда пишет пояснение вокруг JSON. Теперь принимается ровно один JSON-объект; два объекта или вложенное действие остаются `protocol_error`.

В этих 18 запусках Jev ни разу не передал управление, поэтому помощь J1 не сработала. Она проверена отдельно: сценарий вместо Jev передаёт управление на странице результатов, настоящая LLM заканчивает задачу, 3 из 3 подтверждены oracle, стоимость помощи около $0.00045 за запуск (`console.txt`). Счётчик шагов помощи в этом прогоне занижен на 1, потом исправлен.

`test_v06_browser_*.py` на Windows: 191 тест, OK (до исправления счётчика; после него повторно прогнан один изменённый тест).

## Что мешает приёмке

### Раздел 17, пункт 1: функциональные проверки F01-F12 не закрыты

Статус F-проверок нигде не вёлся. Ниже чтение самих тестов, а не их прогон; несколько утверждений про отсутствие тестов и возможности проверены отдельно по коду. Полностью покрыт только F07.

```
F01 общий сайт    нет динамической формы: на демо-сайте нет JavaScript
F02 актуальность  нет смены document/frame; остальное частично
F03 TextSlots     точный payload и неизвестный слот есть; подмена и новая версия частично
F04 допуск        нет чужой вкладки
F05 отмена        нет порядка commit до cancel и зависшего драйвера; закрытие частично
F06 эффекты       нет автосохранения, Enter, повтора через LLM; потеря ответа частично
F07 handoff       покрыт
F08 проверка      нет старого уведомления и неизвестного scope; другая карточка частично
F09 ограничения   нет сохранения подтверждённого fail в цепочке
F10 наблюдение    нет focus и handoff; scroll частично
F11 возможности   frames, cross-origin и shadow DOM объявлены false и не проверялись
F12 трасса        нет проверки stdout/stderr на секреты и evidence у completed; регрессии частично
```

Пункт 1 раздела 17 требует все эти проверки, поэтому режим по умолчанию сейчас выбрать нельзя, каким бы ни был результат сравнения. F11 допускает отрицательные проверки, поэтому frames и shadow DOM можно закрыть честным «не поддерживается». Но тогда 6 задач этой группы в наборе будут провалами возможностей у всех режимов.

### Нет набора сайтов

Нужны 30 задач на 10 сайтах и принятый заранее oracle. На чужом сайте сейчас `completed` недостижим: `runtime.no_uncertain_repeats` и эффекты подтверждает только зарегистрированный источник, а он есть лишь у демо-сайта.

## Не установлено

- Стоимость на настоящих сайтах: страницы там больше, и оценка по демо-сайту занижена.
