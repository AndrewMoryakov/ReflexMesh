# V0.6: первые прогоны с настоящим Jev, 2026-10-13

Датированный отчёт о первых прогонах общего браузерного пути V0.6 с **настоящим Jev** (не script, не заглушка,
не laya). Одна демо-задача, два прогона; это свидетельство того, что Jev выбирает действия в этом пути, а не
оценка его качества и не сравнение Jev/LLM (M5).

## Что запускалось

- Задача `experiments/v06/tasks/order-note.json` на демо-сайте `experiments/v06/site/server.py` (сайт без
  разметки ReflexMesh; у ядра нет сценария для него).
- Провайдер `--action-provider jev`: SystemOneHarness → OpenRouter `/api/alpha/decisions`, запрошена
  `~typesafe/jev-latest`, обслужила **`typesafe/jev-1.13-20260917`** (`served_model` в каждом `decision_received`,
  у всех вызовов непустой `request_id`). Ключ — из файла 0600 вне репозитория; в журнал он не попадает.
- Компоненты совпадают с закреплёнными: SOH `ab8e8f0`, Browser Use `5c892e0` (`components.*.matches_pin`),
  Chrome for Testing 153.0.8010.12, песочница Chromium выключена (`REFLEXMESH_CHROME_NO_SANDBOX=1`, этот хост).

```sh
set -a; . ~/.config/reflexmesh/openrouter.env; set +a
.venv/bin/python experiments/v06/site/server.py --port 8770 &
.venv/bin/reflexmesh browser run --input experiments/v06/tasks/order-note.json \
  --output-dir ./run-jev --action-provider jev
curl -s http://127.0.0.1:8770/__state      # что сайт получил на самом деле
```

## Прогон 1 (код `33799e4`): задача пройдена, заметка сохранена девять раз

| Решение | Действие Jev | Уверенность | `goal_reached` |
|---|---|---|---|
| 1 | ввести слот `order@1` в «Order number» | 0.99 | 0.01 |
| 2 | нажать Search | 0.80 | 0.02 |
| 3 | открыть «Заказ №125» | 0.92 | 0.03 |
| 4 | ввести слот `note@1` в «Note» | 0.84 | 0.03 |
| 5 | нажать «Save note» | 0.83 | 0.07 |
| 6–26 | снова ввести заметку и снова сохранить (восемь пар и ещё один ввод; четыре решения отсечены порогом 0.7) | 0.45–0.92 | 0.05–0.31 |
| 27–29 | нажатия ниже порога | 0.57–0.67 | 0.11–0.15 |

Итог `incomplete/needs_handoff` (`no_confident_action`), 29 вызовов модели, 23 команды, 40.5 с. Сайт по своему
`/__state`: **у заказа 125 девять заметок, девять POST** ([site-counts.json](evidence/V0.6-jev-run-2026-10-13/site-counts.json)).

Путь и выбор слотов — модели: операцию, цель и `type_text__value` (`order@1`, `note@1`) выбрал Jev, переходника
нет. Ошибка суждения тоже его: после первого сохранения `goal_reached` ни разу не поднялся выше 0.31, и `finish`
он не выбирал. Почему — не установлено (текст страницы в журнал не пишется, поэтому из свидетельств не видно,
что именно Jev увидел в списке заметок).

Ошибка контроля — наша. Правило V0.6 §9 «одинаковая операция с неизвестным эффектом не становится новой из-за
нового observation» не выполнялось: проверка повтора (и оценка `runtime.no_uncertain_repeats`) узнавала действие
по ключу «действие + состояние страницы», а каждое сохранение добавляло заметку в список и меняло состояние.
Оценка при этом написала «повторной мутации не наблюдалось» — неверно, хотя итог `unknown`, а не `pass`.
Свидетельства: [before-fix-result.json](evidence/V0.6-jev-run-2026-10-13/before-fix-result.json),
[before-fix-trace.jsonl](evidence/V0.6-jev-run-2026-10-13/before-fix-trace.jsonl).

## Исправление

Изменяющее действие (риск `write`: click, type_text, select_option) получает ключ «то же действие на том же
документе»: роль, имя, опция, адрес перехода, слот и URL страницы (query — отпечатком, журнал хранит только пути),
без текста страницы. Повтор ключа в попытке отклоняется до отправки как `repeated_mutation`; цикл смотрит снова,
и три цикла без нового состояния дают `needs_handoff/no_progress`. Тот же ключ использует оценка
`runtime.no_uncertain_repeats`, поэтому девять сохранений теперь дали бы `fail`. Тесты:
`tests/test_v06_browser_control.py` — оба новых падают на прежнем коде.

Цена: тот же ввод в то же поле той же страницы второй раз не выполняется, даже если сайт очистил поле после
ошибки валидации; это handoff, а не повтор «на всякий случай». Search на форме и затем на странице выдачи — разные
документы и по-прежнему допустим.

## Прогон 2 (после исправления): одна заметка, остановка

Те же пять решений и пять команд (уверенность 0.99, 0.77, 0.88, 0.87, 0.79), затем Jev снова предлагает ввести
заметку: первый раз ниже порога (0.45), второй раз (0.77) — **`admission_rejected: repeated_mutation`**, ничего не
отправлено, третий ниже порога; итог `incomplete/needs_handoff` (`no_progress`). 8 вызовов, 6 команд (с начальной
навигацией), 13.2 с. Сайт: **одна заметка, один POST**. Браузер закрыт, профиль удалён, процессов не осталось.
Свидетельства: [result.json](evidence/V0.6-jev-run-2026-10-13/result.json),
[trace.jsonl](evidence/V0.6-jev-run-2026-10-13/trace.jsonl).

Это всё ещё не `completed`: критерий `note_saved` (`revisit_match`) — `unknown`, verifier'а нет (M4); `ownership`
и `no_uncertain_repeats` — `unknown`.

## Что это значит для M2

Определение M2 — «Jev действительно выбирает действия и TextSlots в этом пути; короткие браузерные проверки
показывают выбор, действие и проверку эффекта» — на демо-задаче выполнено: выбор, отправка и `ui_effect` каждой
команды записаны, вызовы Jev подтверждены `served_model` и `request_id`. Не показано: что-либо кроме одной
задачи, полезность Jev против LLM (M5), калибровка порога 0.7 для этой модели.

## Не проверено

- Почему Jev не считает цель достигнутой после сохранения; помог бы ему явный признак сохранения в наблюдении — не
  исследовано.
- Вызовы не сверены с журналом OpenRouter (в V0.2 так делалось); свидетельство — ответы сервиса в трассе.
- Ни одной другой задачи и ни одного сайта, кроме демо.
