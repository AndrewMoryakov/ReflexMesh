# ADR-0001: устранение неоднозначностей инвариантов

Дата: 2026-09-23. Статус: принято для реализации. Код исполнения ещё не реализован.

Основание: ревью обнаружило смешение промежуточного fail с итоговым,
неопределённые гонки отмены/handoff, недостаточное условие повтора и
неполную привязку свидетельств к цели.

| INV | Решение | Проверка при реализации соответствующего пути |
|---|---|---|
| 08, 09 | Постусловия оцениваются в финале; нарушения ограничений сохраняются. Критерии непустые, свидетельства относятся к нужной ревизии и объекту. | Промежуточный fail → финальный pass допустим; нарушение не стирается; старое сообщение «сохранено» не принимается. |
| 10, 12 | Один терминальный переход; поздние ответы только дополняют свидетельства. Передача управления учитывает незавершённые действия. | Обе очередности cancel/complete; отсутствие новых действий старого владельца. |
| 11 | Неизвестный эффект не повторяется без доказанного неприменения или дедупликации. | Сервер принял форму, ответ потерян, UI ещё старый: второй отправки нет. |
| 03, 04 | Адаптеры различают пошаговый и автономный контроль. | Автономному engine нельзя выдать задачу с необеспечиваемыми ограничениями. |
| 05 | Кандидаты имеют наблюдение, цель и предусловия; атомарность UI не обещается. | Устаревшая/неоднозначная цель требует reobserve. |
| 15 | Постоянно требование обоснованной сложности; порядок интеграции остаётся планом. | Дополнительный адаптер имеет измеримое основание, в том числе latency/quality/control. |
| 16 | Критерии эксперимента задаются до измерения. | Отчёт сопоставляется с заранее сохранённым планом. |

Последствие: статусы будущего runtime проектируются отдельно от результата
проверки цели. V0.1 реализует только routing-контракты и не заявляет соблюдение
ещё не реализованных execution-инвариантов.
