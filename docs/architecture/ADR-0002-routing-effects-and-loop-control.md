# ADR-0002: эффекты routing и граница управления micro-loop

Дата: 2026-09-24. Статус: принято как требование; новые execution-функции не реализованы.

## Причина

Ревью документации выявило чрезмерно широкую формулировку INV-03 «routing
не меняет внешнее состояние»: реальные запросы модели имеют стоимость и
диагностические записи. Также runtime и SystemOneHarness оба описывали
управление циклом, без доказанной границы взаимодействия.

## Решение

INV-03 запрещает исполнение пользовательских действий и изменение целевой
среды задачи при routing. Предусмотренные запросы провайдеру решений, их
стоимость и диагностические записи допускаются и учитываются отдельно.
Это не разрешает запуск произвольного инструмента ради «диагностики»,
обход политики или выполнение выбранного маршрута самим маршрутизатором.

Runtime владеет попыткой, лимитами, политикой и терминальным исходом;
SystemOneHarness — внутренним циклом наблюдений и предложений. Второй
конкурирующий цикл действий не создаётся. Для пошаговой интеграции V0.4
доказывает pre-action veto, получение результата, остановку последующих
действий и отсутствие перезапуска по позднему ответу.
При отсутствии этих возможностей используется классификация автономного
engine согласно INV-03; неприменимые гарантии не декларируются. Выбор
адаптера/ограниченного сценария/другого backend фиксируется по результатам spike.

## Последствия и проверки

- INV-03 меняется только в части определения допустимых эффектов routing;
  INV-01–02 и INV-04–16 сохраняются.
- Routing-тест отделяет запросы провайдеру и receipts от вызовов executor.
- V0.4 проверяет отклонённый вызов, результат, отмену и поздний ответ на драйвере.
- Наличие HTTP-запроса само по себе не нарушает INV-03, но не закрывает live gate.
- Эти проверки управления пока требования к будущему execution-пути,
  а не дополнительные результаты тестирования текущей версии.
