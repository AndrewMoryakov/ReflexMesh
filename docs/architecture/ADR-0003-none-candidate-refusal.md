# ADR-0003: смысловой отказ маршрутизации через кандидата NONE

Дата: 2026-09-24. Статус: принято; реализовано в адаптере JevRouter (V0.2 contract, additive).

## Причина

[V0.3](../research/V0.3-routing.md) показал, что Jev выбирает лучший из переданных
кандидатов, даже если ни один не подходит: корректный отказ 25%. [V0.3b](../research/V0.3b-refusal.md)
сравнил четыре способа по заранее утверждённому протоколу. Кандидат `NONE`, добавленный к
разрешённым (вариант J1), дал корректный отказ 96% (100% при запрещённом нужном классе,
92% вне каталога) без ложных отказов и без потери точности на 60 обычных задачах, при той же
задержке и стоимости. Показывать Jev запрещённые классы (J2/J3) не требуется.

## Решение

- Адаптер JevRouter по умолчанию добавляет к разрешённым кандидатам `NONE` с описанием,
  измеренным в V0.3b (текст фиксирован в коде как `NONE_DESCRIPTION`; изменение текста —
  новый эксперимент).
- Если upstream выбрал `NONE`, итог: `status=abstained`, `route=null`,
  `reason_code=upstream_no_fitting_route`, exit 3. Выбор `NONE` сохраняется в
  `trace.upstream.selected` и вероятностях для аудита.
- `NONE` не является маршрутом (`Route`), не может стать `route` и не проходит в исполнение.
- При пустом пересечении capabilities и allowed_routes запроса, как и раньше, нет:
  `NONE` не превращает пустой набор в сетевой вызов.
- Отключение для воспроизведения прежнего поведения: `--no-none-candidate`
  (CLI) / `none_candidate=False` (API). Протокол V0.3 и его harness используют отключение.
- Запрещённые классы в Jev по-прежнему не передаются (решение V0.2 сохраняется).

## Последствия

- Схема ответа 0.2 не меняется; добавлен reason_code `upstream_no_fitting_route`.
- Проверка ответа ожидает набор кандидатов «разрешённые + NONE».
- Сборщики live-пакетов учитывают `NONE` в наборе кандидатов.
- Жёсткой гарантией остаётся фильтр allowed_routes; `NONE` — вероятностный смысловой
  отказ, а не авторизация. Пропуск возможен (в V0.3b: «Schedule a cron job» → LLM).

## Проверка

- Контрактные тесты: payload содержит `NONE` последним; выбор `NONE` → abstained;
  `NONE` не выбирается маршрутом; отключение восстанавливает прежний payload.
- Демо-проверка закреплённого upstream (`scripts/check_jevrouter_http.py`).
- Live end-to-end через CLI ReflexMesh на наборе V0.3b: результат должен совпасть
  с J1 по порядку величины; расхождение фиксируется в отчёте, а не подгоняется.
  Выполнено: [отчёт](../research/ADR-0003-live-check.md) — совпадение с J1 (control 1.00, отказ 0.958).
