## Как поддерживать документы согласованными

У каждого вида сведений свой источник: цель — North Star, концепция — архитектура,
нормативные ограничения — инварианты, порядок — roadmap, факты готовности — status
и связанные отчёты. Спецификация задаёт контракт отдельного инкремента;
описание будущего поведения не считается доказательством его реализации.

При изменениях:

1. Перед реализацией прочитайте целевую архитектуру, инварианты, статус и спецификацию этапа.
2. Изменение инварианта оформляйте ADR с причиной, последствиями и проверкой.
3. Новую функциональность связывайте с приёмочными свидетельствами и обновляйте STATUS/ROADMAP.
4. Команды и флаги синхронизируйте с README и спецификацией.
5. Сохраняйте исторические отчёты: новый прогон получает собственную дату и кодовую базу.

При расхождении кода и документа не объявляйте требование выполненным:
зафиксируйте расхождение и исправьте код или явно согласованную спецификацию.
Требования не ослабляются автоматически вслед за текущей реализацией.
