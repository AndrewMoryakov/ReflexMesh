# V0.6 browser path: install, run, read the result

Scope: the generic browser path built for V0.6 **M1–M2** (`reflexmesh browser run`). It runs one
bounded browser subtask on a site the core has no scenario for. It is not the fixture runtime
(`reflexmesh run`, see [V0.5-local-run](V0.5-local-run.md)) and not the whole browser MVP:
handoff continuation, the general verifier and the Jev/LLM comparison (M3–M5) do not exist yet.
What was run, and what was not, is in [the M1–M2 evidence](../research/V0.6-M1-M2-2026-10-11.md);
the contract is [V0.6 Browser Core](../specs/V0.6-browser-core.md).

## Install

Linux or WSL, Python 3.11+. The core itself has no dependencies; the browser capability does.

```sh
python -m venv .venv
.venv/bin/pip install -e .

# SystemOneHarness at the pinned commit
git clone https://github.com/HarnessRouter/SystemOneHarness.git ../SystemOneHarness
git -C ../SystemOneHarness checkout ab8e8f08b4a6268c0633a474423d556599ee06a4
.venv/bin/pip install -e ../SystemOneHarness

# Browser Use at the pinned commit (the dependency the adapter was written against)
.venv/bin/pip install --no-deps \
  "git+https://github.com/browser-use/browser-use.git@5c892e013a73e6622e6f50336e1eb0aa2c4405f2"

# A Chromium; the headless shell is enough and small
.venv/bin/pip install playwright && .venv/bin/python -m playwright install chromium-headless-shell
export REFLEXMESH_CHROME=$(ls ~/.cache/ms-playwright/chromium_headless_shell-*/chrome-headless-shell-linux64/chrome-headless-shell)
```

Every result carries a `components` block: the installed SOH and Browser Use commits next to the
pinned ones (`matches_pin`), the Chromium version, the provider and whether the sandbox was on.

**Chromium sandbox.** It is on by default. Some hosts forbid unprivileged user namespaces
(Ubuntu 23.10+ with AppArmor: `No usable sandbox!`); there pass `--no-sandbox` or set
`REFLEXMESH_CHROME_NO_SANDBOX=1`. That is a per-host decision and is recorded in the result
(`components.chromium_sandbox`). Do not use it for sites you do not control without thinking about it.

**Temporary files.** Browser Use copies a custom Chrome profile into `/tmp` unless the directory
name carries its marker; the adapter names its profile `browser-use-user-data-dir-reflexmesh-*`,
verifies that Chrome really uses it and removes it. If `/tmp` is a RAM disk, set `TMPDIR`.

## Run the demo scenario

The demo site (`experiments/v06/site/server.py`) is an ordinary order desk: a nav, a search form,
a results list, an order page with a note form. It has no ReflexMesh markup; the core has no
scenario for it.

```sh
.venv/bin/python experiments/v06/site/server.py --port 8770 &

.venv/bin/reflexmesh browser run \
  --input experiments/v06/tasks/order-note.json \
  --output-dir ./run-001 \
  --action-provider script --script experiments/v06/tasks/order-note.script.json
```

`--action-provider script` plays fixed steps against the options each step offers, picking them by
their visible description. It proves the mechanics (observation, admission, dispatch, effects,
cleanup). It says **nothing about Jev**.

### With the real Jev provider

The key is read from the environment only; never put it in a task, an argument or a chat.
Keep it in a file only you can read, outside the repository:

```sh
install -m 600 /dev/null ~/.config/reflexmesh/openrouter.env      # then add one line yourself:
# OPENROUTER_API_KEY=...
set -a; . ~/.config/reflexmesh/openrouter.env; set +a

.venv/bin/reflexmesh browser run \
  --input experiments/v06/tasks/order-note.json --output-dir ./run-jev-001 \
  --action-provider jev            # optional: --model NAME
```

`TYPESAFE_API_KEY` selects the provider's own API instead. Provider retries are off: every request
is reserved against `max_model_calls` first. `--decisions-url` points the same client at a stand-in
or proxy (https, or http on loopback); it is recorded in `components.decision_provider.config_id`.
Evidence that the real service was used is `decision_requested` / `decision_received` rows in
`trace.jsonl` with `served_model`, `request_id` and token usage; without them a run is not a Jev run.

### With a local laya-browser server

`--action-provider laya` asks a [laya-browser](../research/V0.6-laya-local-provider-2026-10-13.md) server
(`laya_browser.py serve`, the `/v1/systemone` wire) in the format that model was trained on. It needs no key;
`--decisions-url` is required and must be https or http on loopback, so reach a server on another machine
through an ssh tunnel:

```sh
ssh -N -o BatchMode=yes -L 127.0.0.1:8791:<server-address>:8791 <user>@<host> &
.venv/bin/reflexmesh browser run \
  --input experiments/v06/tasks/order-note.json --output-dir ./run-laya-001 \
  --action-provider laya --decisions-url http://127.0.0.1:8791
```

What laya chose and what the translator filled in (the slot to type, `goal_reached`) is recorded per decision
in `translated.derived`; `go_back` and `switch_tab` are not offered to it (they never appeared in its training).
It is not Jev, and its confidence is not calibrated against the 0.7 threshold.

## Watching a run

A separate, read-only page shows each decision, who made it and how long it took. It reads the run
directory (`trace.jsonl` is written line by line, so it updates while the run is going) and can be started
before the run:

```sh
.venv/bin/reflexmesh browser view --run-dir ./run-001          # prints http://127.0.0.1:8780/
```

Per step: the author (`served_model`, so a stand-in, Jev or another model is visible), the chosen action and
the option it pointed at, confidence and the threshold it was judged against, the outcome, and the time split
into observation, decision (our measurement of the whole round trip, next to the provider's own figure),
admission and the browser command. The header gives the number of decisions, total decision time and its share
of the run, median, p95 and maximum. Click a row for the full menu that was offered, with the chosen entry marked.

It binds to loopback only, answers only GET, checks the `Host` header, and shows every value as text (page
text reaches option names). It never writes and never contacts a browser or a provider. Times are differences
between journal events (millisecond resolution); the first navigation includes starting the browser.

## Reading the result

`result.json` is `browser-result/0.1`; `trace.jsonl` is the redacted journal.

| Where | What it tells you |
|---|---|
| `attempt_status`, `stop_reason` | How the attempt ended. This build never reaches `completed`: no verifier for task criteria exists (M4), so a finished run is `incomplete/verification_unknown`. |
| `verification[]` | Criteria (`unknown`, with the reason) and the six `runtime.*` constraints. Permissions, dispatch ordering, immutable slots and budget can `pass` on gate and ledger evidence; ownership and no-uncertain-repeats stay `unknown`. |
| `actions[]` | One row per committed dispatch: option, target role and name, slot reference, driver outcome, `ui_effect` (what the next observation showed) and `effect` (server side: `unknown` unless something settled it). |
| `trace.jsonl` | `observed` → `options_built` → `decision_requested` → `decision_received` → `threshold_judged` → `proposal` → `admission_rejected`/`reobserve` or `dispatch_committed` → `driver_returned` → `effect_assessed` → `terminal`. |
| `budget`, `cleanup`, `components`, `decision` | Steps, model calls and dispatches; whether the browser and profile are gone; versions; requested and served model. |

Slot values never appear in the trace: secrets are always replaced, and normal values of four or
more characters too. Page text and typed content are not stored. A secret slot's value is also
withheld from the decision provider (it gets the reference and "secret value, not shown").

Exit codes: `0` completed, `3` blocked, `4` incomplete, `5` failed, `130` cancelled.

## Checks

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_v06_browser_*.py'   # 96 tests; the 21 real-browser ones skip without REFLEXMESH_CHROME
```

The deterministic modules (`contract`, `control`, `providers`) need no browser. `test_v06_browser_real.py`
needs `REFLEXMESH_CHROME` and the pinned dependencies; without them it is *pending*, not passed.
A fake decision server in that module checks the provider plumbing (key header, call accounting,
no hidden retry) and is not Jev.

## Known limits

- The loop runs in the calling process (a watchdog thread kills the browser if the decision
  provider or driver hangs), not in an isolated supervised process.
- Offered operations: click, type_text, select_option, scroll, wait, go_back, switch_tab, and the
  first navigation. Not offered: key presses, `focus_region`, frames, cross-origin frames, open shadow
  DOM, file upload, drag and drop. Those capabilities are declared `false`, not probed.
- `allowed_origins` is checked on link destinations and tab switches before dispatch. A server-side
  redirect to another origin is **detected after the request** (the run stops `blocked/policy_denied`);
  it is not prevented.
- Starting Chromium occasionally fails (seen once in about twenty starts: Browser Use could not attach to the first
  target); the attempt then ends `failed/executor_error` and a rerun works.
- Clicks and typing can reach a server whatever the UI shows: their `effect` stays `unknown`.
- A repeated action is not caught: Browser Use renumbers every element on every capture, so SOH's
  same-action check sees the same button as a new one each time (a laya run clicked Search 60 times until the
  deadline). Only the deadline and the step and call budgets stop it.
- Browser Use lists the controls near the window. Anything outside it makes `coverage` `partial`
  (`more_content_below`/`above`, `next_window: scroll`); a scroll reveals more. The 200-control cap is also
  reported (`control_limit`) but no test reaches it.
