# V0.6 — ReflexMesh over MCP and from Pi

The [V0.6 specification](../specs/V0.6.md) defines the contract; this guide shows how to run it. Browser attempts need the same environment as [V0.5](V0.5-local-run.md): Python 3.11+, the pinned SystemOneHarness, Browser Use 0.13.10 and a Chromium executable.

## Start the MCP server

```bash
PYTHONPATH=src:../SystemOneHarness python -m reflexmesh mcp \
  --state-dir ~/.local/state/reflexmesh --chrome /path/to/chrome
```

The server speaks MCP over stdio (one JSON-RPC message per line). Each submitted attempt gets a directory `STATE/attempts/<attempt_id>/` with `task.json`, the CLI's `out/result.json`, `out/trace.jsonl`, `out/evidence.jsonl` and logs. `--jev-url` points at a loopback JevRouter for `routing_provider=jevrouter`; `action_provider=jev` uses the SystemOneHarness provider configuration from the environment (`OPENROUTER_API_KEY` or `TYPESAFE_API_KEY`, optional `HTTPS_PROXY`).

Any MCP client can use it, for example:

```json
{"mcpServers": {"reflexmesh": {"command": "python3",
  "args": ["-m", "reflexmesh", "mcp", "--state-dir", "~/.local/state/reflexmesh", "--chrome", "/path/to/chrome"],
  "env": {"PYTHONPATH": "/path/to/ReflexMesh/src:/path/to/SystemOneHarness"}}}}
```

## Use it from Pi

`integrations/pi` is a Pi package with an extension (registers the server) and the `reflexmesh-subtasks` skill. Install it from a checkout, or load it for one run:

```bash
pi install ./integrations/pi     # personal install (loaded from the checkout, not copied)
pi -e ./integrations/pi          # or only for one invocation
```

The extension reads `REFLEXMESH_PYTHON`, `REFLEXMESH_PYTHONPATH`, `REFLEXMESH_STATE_DIR`, `REFLEXMESH_CHROME`, `REFLEXMESH_JEV_URL`, or a full `REFLEXMESH_MCP_COMMAND` JSON array (for example to run the server on another machine over `ssh`). The tools are exposed directly as `mcp__reflexmesh__reflexmesh_submit`, `..._status`, `..._cancel` and `..._continue`.

## The loop

1. `reflexmesh_submit` → `attempt_id`.
2. `reflexmesh_status` with `wait_seconds: 50` until `state=terminal`.
3. `completed` + `task_outcome=pass` is success. Anything else has a `handoff`:
   - `actions[].outcome` distinguishes `done`, `not_done` and `possibly_done`; a `possibly_done` external effect blocks continuation (`unresolved_effect`).
   - `needs_content` names required fields that are empty because no prepared text exists. Prepare it and call `reflexmesh_continue` with `changes.add_text_slots`.
4. `reflexmesh_continue` runs a linked attempt (new revision when the task changes) with the chain's remaining budget, a fresh browser and a fresh baseline; it can only narrow permissions.
