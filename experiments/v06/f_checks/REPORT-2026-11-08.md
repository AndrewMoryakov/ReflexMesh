# F gates of V0.6 section 16: ledger and three passes, 2026-11-08

`ledger.json` maps each requirement of section 16 to the tests that cover it; `run_gates.py` runs them three times,
each pass in a fresh process, and counts an item only when all its tests pass in every pass. `report-edge.json` is
the run on commit `3287e93`, Windows 11, Python 3.13.14, Microsoft Edge 144.

Items closed today by new tests (`FChecks` in `tests/test_v06_browser_real.py`, demo pages under `/fx/` and order

F08's unknown scope is mapped to the verifier's existing binding tests. No product code changed: the runtime already
behaved so; the tests were missing.

## What section 17, item 1 still lacks

- F12's route and fixture API compatibility: the whole suite on Windows ran 806 tests with 9 failures and 290
  errors, nearly all in the V0.5 fixture runtime and the V0.6 API and CLI plumbing, from POSIX-only calls (`fork`
  255 times, `os.getpgrp`, `signal.SIGKILL`, `os.killpg`, `O_DIRECTORY`). That runtime is documented as Linux or
  WSL only. A run on Linux is needed; not done.
- The six partial items above.
- The browser. These passes used Edge 144. With Playwright's `chrome-headless-shell` 1243 on the same machine, four
  tests failed in one pass: the three F06 lost-response tests (no `repeated_mutation` refusal) and the F11 test of a
  frame of another origin. With Chrome 142 on another Windows machine they had passed. Which Chromium build the gates
  are accepted on is not fixed by the spec; why the headless shell behaves differently is not established.
- In the whole-suite run `test_declared_capabilities_are_the_probed_ones` failed once with no observation in its
  trace (the browser did not come up), while it passed in all three ledger passes. Not investigated.
